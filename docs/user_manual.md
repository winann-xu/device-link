# DEVICE LINK 使用手册

> 版本: 1.0.9 | 平台: Windows 10/11 (64位) | 部署: 免安装便携版

## 1. 快速开始

### 1.1 安装

1. 解压 `DEVICE-LINK-v1.0.9.zip` 到任意目录（路径建议使用英文，避免个别环境编码问题）
2. 双击 `DEVICE-LINK.exe` 即可运行
3. 系统托盘出现 DEVICE LINK 图标，说明启动成功

### 1.2 首次配置

1. 双击托盘图标或右键 →「打开主界面」
2. 进入「设备管理」→ 添加需要监控的设备（可单个添加或 CSV 批量导入）
3. 进入「告警与通知配置」→ 配置通知通道（邮件 / 飞书 / 企业微信），勾选启用并保存
4. 返回「实时仪表盘」查看设备在线状态

## 2. 功能概览

### 2.1 实时仪表盘

- 按子系统分组展示所有设备卡片
- 状态颜色：在线（绿色）｜ 离线（红色）｜ 待定（黄色）｜ 维护中（灰色）｜ 未启用（灰色）
- 支持按设备名 / IP 搜索，快速筛选（全部 / 在线 / 离线 / 待定 / 维护中）
- 每 2 秒自动刷新；左下角状态栏实时显示：在线 X/Y、离线、待定统计

### 2.2 设备管理

- **添加设备**：填写名称、IP、子系统、探测方式、端口、检查间隔、超时、失败/恢复阈值
- **批量操作**：勾选多台设备 → 批量删除 / 批量维护
- **CSV 导入**：按模板填写后导入，适合批量录入（空"是否启用"默认视为启用）
- **CSV 导出**：将当前设备列表导出为 CSV
- **测试探测**：选中设备 → 点击测试 → 即时查看连通性结果

### 2.3 历史统计

- 在线率概览：今日 / 最近7天 / 最近30天
- 离线排行榜：最近 N 天离线次数排名（Top 10）
- 告警日志：全部告警事件，支持确认与筛选

## 3. 探测与状态判定（详细）

### 3.1 探测策略

| 步骤 | 说明 |
|------|------|
| 主探测 | ICMP Ping（默认超时 3 秒），最快、最轻量 |
| TCP 复核 | Ping 失败且设备配置了端口时，自动用 TCP 连接复核（防止 ICMP 被防火墙拦截误报） |
| 复核通过 | 判定在线，不计入失败次数，界面标注"TCP复核" |
| 复核失败 / 无端口 | 判定离线，计入连续失败次数 |

### 3.2 状态机与误报抑制

设备状态：**未知 → 在线 / 待定失败 / 离线**。

- 首次探测成功：未知 → 在线
- 在线后失败 1 次：进入**待定失败**（黄色，不告警）
- 连续失败达到阈值 N（默认 3）：判定**离线**，触发告警
- 离线后连续成功达到阈值 M（默认 2）：判定恢复，触发恢复通知
- 维护中的设备照常探测、显示状态，但**不产生告警**

### 3.3 检查间隔

每台设备可独立设置检查间隔（默认 30 秒）。程序启动或批量导入后会随机错峰，
避免上千台设备在同一秒同时探测造成网络/数据库拥塞。

## 4. 告警与通知配置（详细）

进入「告警与通知配置」页面，包含三大区域：**通知通道**、**告警合并策略**、
**全局告警规则**。所有修改需点击右下角「💾 保存配置」才生效并写入
`config/config.yaml`。

### 4.1 通知通道（邮件 / 飞书 / 企业微信）

三个通道以标签页展示，每个通道都有独立开关、配置字段和「📨 测试发送」按钮。

> 重要：勾选「启用此通道」后必须点击「保存配置」，真实告警才会走该通道。
> 测试发送成功只代表配置连通，不代表通道已启用。

#### 4.1.1 邮件通道

| 字段 | 说明 |
|------|------|
| 启用此通道 | 是否启用邮件通知 |
| SMTP 服务器 | 发件邮箱的 SMTP 地址，如 `smtp.126.com`、`smtp.qq.com` |
| 端口 | 默认 465（隐式 SSL）；使用 587 时自动切换 STARTTLS |
| 用户名 | 发件邮箱地址 |
| 密码 | SMTP 授权码（QQ/126 等邮箱需在邮箱设置中开启 SMTP 并生成**授权码**，非登录密码） |
| 收件人 | 逗号分隔的多个收件人邮箱 |
| 测试发送 | 发送一封真实测试邮件，显示耗时与结果 |

邮件主题格式：`[DEVICE LINK][严重/已恢复/升级/摘要/每日清单/测试] 设备名`。
邮件正文为 HTML 模板，按事件类型使用不同配色（红=离线、绿=恢复、橙=升级、蓝=摘要/清单）。

#### 4.1.2 飞书通道

| 字段 | 说明 |
|------|------|
| 启用此通道 | 是否启用飞书通知 |
| Webhook URL | 飞书群机器人 Webhook，格式 `https://open.feishu.cn/open-apis/bot/v2/hook/xxx` |
| 测试发送 | 发送一张真实卡片（与告警同款路径） |

创建机器人：飞书群 → 设置 → 群机器人 → 添加机器人 → 自定义机器人 → 复制 Webhook。

#### 4.1.3 企业微信通道

| 字段 | 说明 |
|------|------|
| 启用此通道 | 是否启用企微通知 |
| Webhook URL | 企微群机器人 Webhook，格式 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx` |
| 测试发送 | 发送一条 markdown 测试消息 |

注意：企微机器人限速 **20 条/分钟**，超出自动限速，消息大于 4096 字节自动截断。

### 4.2 告警合并策略

#### 4.2.1 启用告警合并摘要

- 开启后，时间窗口内的多条离线告警**合并为一封摘要**发送，避免告警风暴。
- 摘要内容包含：离线台数、涉及子系统数、每台设备的 名称/IP/子系统/离线时间。
- 关闭后，每台设备离线立即单独发送告警。

#### 4.2.2 合并时间窗口

- 可设置 1~60 分钟（默认 5 分钟）。
- 窗口从第一条离线告警开始计时，窗口到期时把窗口内的所有离线事件合并发送。

#### 4.2.3 单封摘要最多

- 单封摘要最多携带的事件数（默认 50，可设 5~200）。
- 超出部分自动进入下一窗口/下一封，不丢失。

#### 4.2.4 紧急绕过（同子系统 ≥ 5 台立即发送）

- 当**同一子系统**同时离线设备 ≥ 5 台时，判定为紧急事件，**忽略时间窗口立即发送**。
- 用于大面积故障时第一时间通知，不等合并窗口。

#### 4.2.5 每日 08:00 离线设备清单（v1.0.9 新增）

勾选「每日 08:00 发送离线设备清单」后，系统**每天早上 8:00** 自动发送一封
「每日离线设备清单」通知（邮件为主，已启用的飞书/企微通道同样会收到）。

规则：

| 规则 | 说明 |
|------|------|
| 发送时间 | 固定每天 08:00（可在 `config.yaml` 的 `notify.daily_report.send_time` 调整） |
| 统计口径 | 只统计**当前离线**设备（`status=offline`）；待定（pending_failure）不算 |
| 维护设备 | 维护中设备不计入清单 |
| 未启用设备 | 未启用设备不计入清单 |
| 数量为 0 | 当天当前离线设备为 0 台时**不发送邮件**，仅在日志记录 |
| 重复发送 | 每天只发送一次；程序当天重启也不会重复发送（记录在 `logs/daily_report_state.json`） |

清单内容：设备名、IP、子系统、最近探测时间、离线时长。

### 4.3 全局告警规则

#### 4.3.1 失败阈值 N

- 连续失败多少次判定离线（默认 3，可设 1~10）。
- N=1 表示一次失败立即判定离线并告警。
- 保存后批量应用到全部设备与运行中的调度器。

#### 4.3.2 恢复阈值 M

- 离线后连续成功多少次判定恢复并发送恢复通知（默认 2，可设 1~5）。

#### 4.3.3 冷却窗口

- 同一设备两次离线告警之间的最小间隔（15/30/60 分钟，默认 30 分钟）。
- 冷却期内同一设备再次离线只记录、不重复发送，防止反复抖动刷屏。

#### 4.3.4 升级时间

- 可设置：关闭 / 5 / 15 / 30 / 60 分钟。
- 离线告警在**未被确认**的情况下持续超过设定时间，自动发送**升级通知**。
- 确认告警（历史统计 → 告警日志 → 确认）后停止升级。
- 每事件最多升级 3 次（防止无限轰炸），可在 `config.yaml` 的
  `notify.escalation_max_count` 调整；总开关 `notify.escalation_enabled`。

### 4.4 保存配置与生效方式

- 点击「保存配置」后：写入 `config.yaml` → 批量更新全部设备阈值 →
  热更新运行中的状态机 → 重建通知通道。
- 提示框中会显示：启用通道数、合并摘要开关/窗口/上限、每日清单开关、
  升级策略、已应用阈值设备数。

## 5. 告警完整流程（以一台设备为例）

```
设备探测失败 1 次
  → 进入"待定失败"（黄色，不告警）
连续失败达到 N 次（默认 3）
  → 判定离线 → 记录告警事件 → 进入合并窗口
合并窗口到期（或同子系统 ≥5 台紧急绕过）
  → 发送摘要/单独告警到已启用通道
持续未确认超过升级时间
  → 发送升级通知（每事件最多 3 次）
设备连续成功达到 M 次（默认 2）
  → 判定恢复 → 发送恢复通知（实时，不合并）
每天早上 08:00（若启用）
  → 发送当日离线设备清单（0 台不发送）
```

## 8. 配置项速查（config/config.yaml）

```yaml
notify:
  digest:
    enabled: true                    # 告警合并摘要总开关
    window_seconds: 300              # 合并窗口（秒），5 分钟
    max_events_per_digest: 50        # 单封摘要最多事件数
    send_immediate_if_critical: true # 同子系统≥5台立即发送
  daily_report:
    enabled: false                   # 每日 08:00 离线清单开关
    send_time: "08:00"               # 发送时间（24 小时制）
  email:                             # 邮件通道（字段见 4.1.1）
    enabled: false
    smtp_host: ""
    smtp_port: 465
    smtp_user: ""
    smtp_password: ""                # 保存时自动 AES 加密
    recipients: []
  feishu:
    enabled: false
    webhook_url: ""
  wecom:
    enabled: false
    webhook_url: ""
  retry_count: 3                     # 发送失败重试次数
  retry_backoff_base_seconds: 5      # 重试退避基础秒数
  cooldown_seconds: 1800             # 冷却窗口（秒），30 分钟
  escalation_enabled: true           # 升级总开关
  escalation_minutes: 15             # 升级时间（分钟）
  escalation_max_count: 3            # 每事件最多升级次数
monitor:
  default_interval_seconds: 30       # 默认检查间隔（秒）
  default_timeout_ms: 3000           # 默认探测超时（毫秒）
  default_failure_threshold: 3       # 失败阈值 N
  default_recovery_threshold: 2      # 恢复阈值 M
  max_workers: 50                    # 探测线程池大小
  max_submit_per_tick: 50            # 单轮最多提交任务数
  jitter_schedule: true              # 首轮错峰
watchdog:
  enabled: true                      # 看门狗总开关
  heartbeat_interval_seconds: 5      # 健康检查间隔
  heartbeat_timeout_seconds: 15      # 心跳超时阈值
  max_restart_attempts: 3            # 连续崩溃最大重启次数
  restart_cooldown_seconds: 30       # 重启冷却
  healthy_threshold_seconds: 300     # 稳定运行多久后复位重启计数
```

## 9. 常见问题

### Q: 设备明明在线但显示离线？

检查 ICMP 是否被防火墙禁止。可在设备配置中设置端口启用 TCP 复核；
若仍误报，可提高失败阈值 N 或把设备加入维护模式（维护中不告警）。

### Q: 邮件通知发送失败？

检查 SMTP 地址/端口/授权码是否正确。QQ/126 邮箱需使用**授权码**而非登录密码；
465 端口走 SSL，587 端口走 STARTTLS。发送日志见 `logs/device-link.log`。

### Q: 告警没收到但日志显示"发送成功"？

确认通知通道已勾选「启用」并点击「保存配置」；测试成功不代表真实告警已启用。
启动时若日志出现"告警引擎当前无启用通知通道"，说明没有可用通道。

### Q: 如何批量添加设备？

设备管理页面 →「📥 导入CSV」→ 按模板填写（设备名,IP,子系统,探测方式,端口,
检查间隔,失败阈值,是否启用）→ 导入。设备名重复的行会被跳过并提示。

### Q: 日志里出现"设备状态落库失败：database is locked"？

多为瞬时数据库写并发导致，v1.0.8 起已自动回滚不会持续；若频繁出现请检查
是否同时运行了多个实例，或把 `monitor.max_submit_per_tick` 调低。

### Q: 如何让程序开机自启？

右键托盘图标 →「开机启动」→ 自动在启动文件夹创建快捷方式。

### Q: 程序崩溃后会自动恢复吗？

程序内置三层看门狗：内部健康检查（心跳超时自动重启）、独立看门狗进程
（异常退出自动拉起，连续 3 次崩溃停止重试）、开机自启。

## 10. 技术支持

- 日志文件: `logs/device-link.log`
- 数据库: `data/device-link.db`（可用 SQLite 工具查看）
- 配置文件: `config/config.yaml`
- 问题排查顺序：先看日志中的 ERROR/WARNING → 检查通道配置 → 检查网络/防火墙
